### Security principles

* No production credentials in Git
* Secrets isolated from public source code
* Private keys excluded from the repository
* Logs and diagnostic archives excluded
* Public OpenPGP infrastructure under `.well-known`
* Responsible disclosure through `security.txt`
* Repository-level secret checks before publication

## Software philosophy

I prefer systems that are:

**Simple where possible.
Explicit where necessary.
Observable by design.
Secure by default.
Documented enough to survive their creator.**

Good software should not merely work.

It should be possible to understand **why** it works.

---

## Ethics & technology

Technological capability alone is not sufficient.

The questions that interest me are also:

* Should we build it?
* Who benefits from it?
* Who controls the data?
* Can the system be independently understood?
* Can its decisions be challenged?
* Does efficiency preserve human dignity?
* What happens when technology fails?

For me, technological progress has value only when it remains connected to **responsibility, knowledge and human values**.

## Public cryptographic identity

My website supports public OpenPGP discovery through:

```text
/.well-known/openpgpkey/
```

and publishes a public OpenPGP key.

Private cryptographic material is never intended to be stored in public repositories.

## Responsible disclosure

Security information for my website is available through:

```text
https://fabriziopapa.it/.well-known/security.txt
```

Security vulnerabilities should be reported responsibly rather than disclosed through public issues containing exploitable details.
